# 浏览器存储开发约定

## idb 接入

浏览器数据仍存放在 IndexedDB 的 `nikki` 数据库，版本 12、17 张表。`schema.ts` 声明键、值和索引类型，`database.ts` 统一建表与连接生命周期。此次切换仅改变调用接口，不升级版本或复制数据；相机参数沿用现有数据库表和 ZIP 格式标识，电脑备份目录统一使用「相机参数」，不读取或迁移旧目录名。

- 业务读写使用 `runStoreRequest` 或 `runDatabaseTransaction`。回调内直接等待 idb 请求，不再包装原生 `IDBRequest`。
- 业务连接由 `getDatabase` 复用；不要在调用方关闭它。需要释放时使用 `closeDatabase`。`openDb` 只创建独立连接，适用于隔离的结构检查，调用方自行关闭。
- 仅在表结构改变时提高版本。高版本数据库拒绝打开并通知界面，不能通过删除数据库恢复。
- 动态目录备份适配器跨多种记录类型，因此公共事务执行器使用 idb 的动态表接口；业务读取入口仍需校验持久化数据，类型声明不能证明旧数据有效。

## 事务与备份

事务回调只等待数据库请求；网络、图片解码、哈希与文件读写在事务外完成。所有写入 Promise 都必须等待，多个独立请求可用 `Promise.all` 一起等待。事务执行器还会等待 `tx.done`，请求成功并不等于提交成功。

搭配、家园和相机参数写入自动加入备份修订与变更表，业务数据和日志同事务提交。表写入代理会在同一个调用中安排日志请求，保留并行删除、重建时的顺序。批量更新通过被追踪表的 `put` 完成；不要绕过追踪调用游标 `update/delete`。

`runMaintenanceTransaction` 仅供目录恢复和全站清理使用。调用方负责持有已有的独占锁，并在事务内完成修订核对、队列清理等操作；不能把此入口用于普通编辑。

只读事务遇到明确的连接丢失错误时重连重试一次；写入、配额、校验与约束失败不自动重试。目录恢复继续按页读取记录，图片一次读取一条，最终复制在同一事务内完成。

## 验证

单元测试使用 `fake-indexeddb`。删除测试数据库前先调用 `closeDatabase`，避免共享连接阻塞清理。`idbConnection.test.ts` 覆盖连接复用、异常终止、升级阻塞、高版本保护及日志失败回滚。

运行 `npm run build`、`npm run test:without-d1`；D1 相关测试必须使用隔离本地数据库。jsdom 测试通过 `tests/setupBrowser.ts` 统一使用浏览器存储及兼容其 AbortSignal 的 undici 请求实现，无需设置 `NODE_OPTIONS`；图鉴资源与外部接口模拟通过 `tests/helpers/catalogFetch.ts` 分离。
